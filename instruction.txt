Build a demo web platform called **Visa Selfie**.

## Project Goal

Visa Selfie is a secure intermediary platform for collecting, storing, managing, and auditing facial verification videos for visa applicants.

For now, the demo should focus only on secure client registration, guided facial video capture, storage, and admin management.

## Main Roles

### 1. Administrator
The administrator is the operator managing visa applicants.

The admin must be able to:
- log in securely,
- create a new client/process,
- enter basic client information,
- generate a unique registration link,
- define link expiration automatically at 48 hours,
- copy the link and send it manually through WhatsApp,
- view all submitted clients,
- see process status,
- view submitted client data,
- securely view or download submitted videos,
- delete videos,
- track timestamps and important actions.

### 2. Client / Visa Applicant

The client receives a unique link through WhatsApp.

The client must be able to:
- open the link on mobile,
- see whether the link is valid or expired,
- register using:
  - full name,
  - date of birth,
  - passport number,
  - phone number,
- accept a consent/privacy notice,
- view facial recording instructions,
- proceed to facial video recording,
- record video using the device front camera,
- preview the video,
- retake if needed,
- confirm and submit the recording,
- receive a success confirmation.

## Phase 1 Workflow

1. Admin logs into dashboard.
2. Admin creates a new client/process.
3. Platform generates a unique secure tokenized link.
4. Link expires after 48 hours.
5. Admin manually sends the link using WhatsApp.
6. Client opens the link.
7. Client enters:
   - full name,
   - date of birth,
   - passport number,
   - phone number.
8. Client accepts consent.
9. Client sees recording instructions.
10. Client starts facial recording.
11. Client previews the video.
12. Client either:
   - retakes the video,
   - or confirms submission.
13. Platform uploads the video securely.
14. Video is linked to the correct client/process.
15. Admin sees the process status change to submitted.
16. Admin can review the data and video.
17. Admin can delete the video when no longer needed.

## Recording Guidance

Before recording, show simple instructions such as:
- use good lighting,
- keep the face fully visible,
- remove sunglasses or face coverings,
- look directly at the camera,
- keep the phone steady,
- ensure only one face is visible,
- follow any movement instructions if required.

For the demo, keep the recording flow simple.

Use the front-facing camera.

Support modern mobile browsers.

Prefer WebRTC / MediaRecorder API for browser-based capture.

## Demo Capacity

The demo should initially support approximately:

The system should still be designed so it can scale later.

## Security Requirements

This project handles sensitive personal and biometric-related data.

Implement the demo with strong security defaults.

Required:
- HTTPS-ready architecture,
- secure authentication,
- hashed passwords,
- secure random tokens,
- token expiration after 48 hours,
- no raw token storage if avoidable,
- authorization checks on all admin endpoints,
- signed or protected video access,
- no public video URLs,
- server-side validation,
- file type validation,
- upload size limits,
- CSRF protection where relevant,
- rate limiting,
- audit logging,
- secure HTTP headers,
- environment variables for secrets,
- no secrets committed to Git.

Passport numbers should not be exposed unnecessarily in logs.

## Privacy and Retention

The platform should support:
- explicit consent before recording,
- manual video deletion,
- future automatic retention rules,
- audit trail for deletion,
- clear distinction between active and deleted records.


## WhatsApp

For the demo:
- do NOT implement automatic WhatsApp sending yet.
- The platform should generate the secure client link.
- The admin will copy and send that link manually using WhatsApp Business.

Design the system so WhatsApp Business / Meta Cloud API integration can be added later.


## Appointment Monitoring Bot

The client also requested a future feature that monitors VFS appointment availability and alerts the admin when new appointment slots open.

Do not fully implement aggressive scraping in Phase 1.

For now:
- create a placeholder module,
- define an interface,
- add a basic scheduler structure,
- allow future notification support.

Do not bypass CAPTCHA, authentication protections, rate limits, or anti-bot controls.

Any future monitoring must respect officially accessible endpoints and platform terms.
